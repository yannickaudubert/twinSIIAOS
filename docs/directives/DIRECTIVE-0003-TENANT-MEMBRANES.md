# DIRECTIVE-0003 — Tenant membranes and projections

Status: ACTIVE

## 1. Separation by default

Personal, cabinet/professional and client contexts are separate governed scopes.

No role, model, memory, search index, graph, vault or interface receives cross-scope access merely because the same human operates all of them.

## 2. Movement across a membrane

Only explicitly selected objects may cross a membrane.

A transfer must preserve or add:

- source scope;
- destination scope;
- purpose;
- classification;
- provenance;
- redaction/anonymization when required;
- authority or HumanGate when required;
- retention and revocation rules.

Complete private vaults are never federated by default.

## 3. Reusable knowledge

Methods, patterns, templates and lessons may become reusable only after distillation:

`PRIVATE -> candidate -> redact -> generalize -> provenance/license check -> human review -> reusable/public`

Client-specific facts do not become generic knowledge merely because they are useful.

## 4. Shared and collective projections

A collective/public layer may expose governed contributions, capabilities, missions or selected knowledge objects.

It must not be a backdoor into personal, cabinet or client stores.

## 5. Interface consequence

Every Front C surface must be able to tell the user which scope they are in and why an object is visible.

Cross-tenant search, suggestions or automation are denied by default unless a policy explicitly allows a governed projection.
