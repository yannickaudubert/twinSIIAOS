# DIRECTIVE-0001 — SIIAOS operating doctrine

Status: ACTIVE
Scope: Front A / Front B / Front C / consumer runtimes and interfaces

## 1. Authority

SIIAOS is governed by human mandate, explicit policy, evidence and canonical records.

Models, runtimes, agents, tools, databases, clouds, machines, UIs, graphs, vaults and providers are replaceable means. None of them becomes authority by implementation convenience.

Front A publishes the canonical contract ABI. Front B and Front C consume projections of that ABI.

## 2. Canon is not projection

Keep separate:

- CANON: governed contracts, decisions, records and evidence;
- PROJECTION: UI, graph, RAG, search index, vault view, building/city, reports;
- EXPERIMENT: sandbox, mock, simulation, candidate workflow;
- DEPLOYMENT: a concrete runtime instance;
- OBSERVATION: facts measured from that runtime.

A projection may be rebuilt. Canonical history must remain attributable and governed.

## 3. Reuse before construction

Default sequence:

`REUSE -> COMPOSE -> ADAPT -> BUILD`

No new core, registry, orchestrator, memory system, agent framework, database or service is introduced merely because it is available.

A new component must close a demonstrated capability gap and preserve an exit strategy.

## 4. Local-first

The nominal system must remain useful without a mandatory cloud dependency.

External services, SaaS, hyperscalers, databases, queues, object stores, observability stacks and agent runtimes are providers/adapters unless a specific deployment explicitly promotes them through evidence and human decision.

## 5. Personae are compiled roles

A persona is not a permanently running autonomous component and never grants permissions.

An execution role is compiled from:

`ROLE + MISSION + METHOD + CONTEXT PACK + CAPABILITIES + POLICY`

Rights derive from identity, mandate and policy. HumanGate remains separate from a human provider.

## 6. Truth and maturity are distinct

Truth status uses the canonical vocabulary defined by A01.

Implementation maturity is tracked separately, for example:

`DESIGNED -> CODED -> TESTED -> DEPLOYED -> OBSERVED`

Do not infer runtime truth from implementation maturity.

## 7. Interfaces cannot mint authority

Hall, Mission Workbench, Decision Room, Research Studio, Deliverable Studio, Client Room, Building/City and administrative consoles are governed projections.

Visibility is not authorization. Clicking is not a mandate. A role label is not a ToolGrant.

## 8. No silent duplication

Before creating a new module, repository, radar, hyperveille, memory, registry, agent, workflow engine or UI, inventory the existing capability and classify it.

A parallel implementation requires an explicit reason, migration path and decommissioning rule.

## 9. Agentic action path

The nominal action path is:

`NeedSpec -> ContextPack -> Mission -> compiled roles/capabilities -> Action -> OperationRecord -> Evidence -> HumanGate when required -> Record/Decision -> RETEX`

No critical action bypasses provenance, authority or evidence.
